1. Technical Objective

Build a real-time, automated Natural Language Inference (NLI) engine to classify AI-generated educational answers, utilizing a highly optimized discriminative transformer to achieve sub-200ms latency and human-parity recall on hallucinations.

2. Analytics Formulation & Data Engineering

We framed the verification problem as a strict NLI classification task determining if a Hypothesis (the AI Answer) is entailed by, contradicts, or is irrelevant to a Premise (the Reference Context).

Data Architecture & Cross-Attention Sequence Structuring:

We processed a 21,021-sample educational Q&A dataset with a severe 10:1 class imbalance (82.9% Factual vs. 8.6% Contradiction). To force the model to capture relational semantics rather than simple keyword overlap, we engineered the input sequence to maximize self-attention across the context boundary:

[CLS] Q + A [SEP] Context [SEP]

This specific tensor structure allows the Transformer's attention heads to directly weigh the generated claim against the source truth.

3. Methodology & Architecture

We selected Microsoft's DeBERTa-v3-Large for its specific architectural advantages over standard generative LLMs or standard BERT variants:

  • Disentangled Attention: DeBERTa separates content embeddings from relative position embeddings. This structural awareness allows the model to catch inverted logic or subtle negation swaps that standard BERT variants miss.
  • NLI-Optimized Pre-training: DeBERTa is explicitly pre-trained to measure semantic entailment natively.

Moving from a traditional Logistic Regression baseline (83.5%) to standard BERT (91.4%) and finally to optimized DeBERTa yielded a +14.15% accuracy gain.

4. Model Building: Stratified Ensembling

To eliminate variance and prevent majority-class bias, we implemented Stratified 5-Fold Cross-Validation, preserving the 10:1 imbalance across all splits. We preserved all 5 models to create an "Expert Committee", utilizing Soft Voting to average the probability distributions. This tightened the decision boundaries on nuanced contradictions, outperforming the best individual fold by ~0.2% and reducing the standard deviation to a mere ±0.19%.

5. Performance Results & Inference Infrastructure

Validated on a blind test set of 4,200 samples:

99.91% Factual Recall
95.20% Contradiction Recall

The inference engine was deployed on Azure Managed Online Endpoints utilizing NC-Series VMs (NVIDIA A100 80GB). We implemented BF16 Precision Training/Inference and a shared cache architecture, reducing computational load by 30% and achieving strict real-time SLAs with <200ms latency.

1. Technical Objective

Design a predictive classification architecture to handle extreme class imbalance, high-dimensional noise, and complex non-linear relationships in corporate financial telemetry. We engineered a 3-stage super-ensemble combining Bootstrap Aggregating (Bagging) with a custom Evolutionary Genetic Algorithm, achieving 1st place.

2. The Architecture: A 3-Stage Super-Ensemble

Level 1: Bagging Layer

10 XGBoost models + 10 LightGBM models trained across distinct random seeds & 5-Fold CV.

Level 2: Evolutionary Layer

1 Custom Evolutionary XGBoost (EXGB) model generating synthetic features via crossover & mutation.

Level 3: Meta-Learner

Logistic Regression stacker acting as a calibrated Judge over the 21 OOF probability matrix.

3. Phase 1: Dual-Imputation Strategy

We routed data through two distinct imputation pipelines based on downstream algorithmic processing:

  • Pipeline A (Standard Trees) - Constant Imputation (-999): For XGBoost/LightGBM, we filled NaN values with -999. Gradient boosting decision trees build binary splits and natively learn to treat -999 as a distinct categorical branch, preserving the structural signal of missingness.
  • Pipeline B (Evolutionary Model) - Median Imputation: The EXGB model generates synthetic features via mathematical combination. Using a -999 constant would create massive artificial outliers, destroying linear relationships. We utilized Median imputation as a mathematically neutral baseline here.

4. Phase 2: Brute-Force Engineering & "Scout" Reduction

  • Synthetic Generation: We applied a brute-force interaction approach, calculating pairwise arithmetic operations across all raw columns to expand our feature space to over 16,000 synthetic ratios.
  • Scout Model Reduction: To conquer the Curse of Dimensionality, we trained a fast, shallow "Scout" XGBoost model (eta: 0.1, max_depth: 3, 100 rounds). We extracted the Information Gain of all 16,000 features and aggressively pruned the dataset down to the top 321 most predictive signals.

5. Phase 3: The Bagging Layer (Variance Reduction)

We utilized Bootstrap Aggregating (Bagging) across distinct random seeds to eliminate model instability caused by noisy tabular data:

  • Trained 10 XGBoost models (L2 Reg: 20.0, L1 Reg: 5.0, max_depth: 4) on 10 different seeds.
  • Trained 10 LightGBM models on 10 different seeds.

Every seed was trained using 5-Fold Stratified Cross-Validation, executing over 100 individual training runs and averaging the Out-Of-Fold (OOF) predictions.

6. Phase 4: Evolutionary XGBoost (EXGB)

We developed EXGB—a genetic algorithm wrapper around a boosting framework—to dynamically hunt for non-linear interactions during training:

  1. Initialize: Start with an ensemble of 10 learners.
  2. Train & Extract: Train the first learner for 100 rounds. Extract the top 15 features based on weight importance (Parents).
  3. Crossover & Mutation: Generate 60 new synthetic features by randomly selecting two Parent features and applying a random arithmetic operator.
  4. Survival: Append these 60 "Child" features to the dataset for the next learner. If a child feature improves the gradient, the next tree uses it; if it is noise, it is ignored.

7. Phase 5: The Meta-Learner (Stacking) & Results

We concatenated the Out-Of-Fold predictions from our 21 models (10 XGBoost, 10 LightGBM, 1 EXGB) into a 21-dimensional meta-feature matrix. This was fed into a Logistic Regression model (solver='liblinear', C=0.05) which acted as a "Judge," outputting the final calibrated probability of insolvency.
